# Проверка аналитики и рекомендаций

Тесты запускаются на полном исходном коде общего бота: нужны модули
`db.models`, `db.requests`, `core.keyboards` и все пользовательские роутеры.
В рабочей ветке, где лежат только файлы личного вклада, интеграционные тесты
нужно запускать после объединения с общим MVP либо на его отдельной копии
с заменой четырёх модулей аналитики и рекомендаций.

Из корня полного проекта (Python 3.13):

```powershell
uv run --group prod --with-requirements tests/requirements-analysis.txt python -m pytest tests -q -o asyncio_default_fixture_loop_scope=function
uv run --group lint ruff check src/finfly/services/stats.py src/finfly/services/agents/recommender.py src/finfly/routers/user/stats.py src/finfly/routers/user/advice.py tests
uv run --group lint ruff format --check src/finfly/services/stats.py src/finfly/services/agents/recommender.py src/finfly/routers/user/stats.py src/finfly/routers/user/advice.py tests
```

`conftest.py` задаёт фиктивные ключи, фиксирует время и создаёт отдельную
SQLite-базу в памяти. Рабочая база и настоящие ключи бота не используются.
Telegram API и ответ нейросети подменяются на границе; Dispatcher, роутеры,
FSM, SQL-запросы, модели БД и расчёты работают по-настоящему.

Проверяются переходы между сценариями, защита владельца кнопок, повреждённый
ввод и кэш, отмена запросов, лимиты, возвраты, календарные границы, регулярные
платежи, сигналы необычных операций и экспорт. XLSX открывается через
openpyxl; тест не утверждает, что файл проверен в приложении LibreOffice.

## Договорённости реализации

- `/timezone +03:00` задаёт смещение UTC для операций без даты покупки.
  Начальное значение — UTC+00:00, оно показано в сводке. При сезонном
  переводе часов смещение нужно изменить вручную. Дата покупки из чека
  остаётся календарной датой и не сдвигается.
- Отрицательная сумма — возврат. Также поддерживается будущий атрибут
  `is_refund`; положительная сумма без такого признака остаётся покупкой.
  Возврат уменьшает итог периода, но не средний чек покупок. Переводы
  между своими счетами исключены. Модель и распознавание команды не менялись.
- При возвратах расчёт кэшбэка просит уточнить правила банка; они не
  угадываются. План кэшбэка жадный, зависит от порядка операций и не является
  гарантированно лучшим распределением. Ставки одной карты/валюты/категории
  заменяются при вводе, дубли в расчёте отклоняются.
- Подписки и необычные покупки — вероятностные сигналы по внесённой истории.
  Распознаются недельные, месячные, квартальные, полугодовые и годовые серии.
  Отметка «важна» сохраняется при изменении цены сервиса.
- Прогноз появляется с пятого числа. Экспорт ограничен 20 000 последними
  операциями; подпись сообщает число выгруженных и найденных записей.
  CSV защищает текстовые поля от формул апострофом; в CSV он может быть виден.
- Ограничитель запросов действует в одном процессе. При нескольких процессах
  его потребуется заменить общим хранилищем. Новый вызов нейросети — не чаще
  одного за 15 секунд на пользователя; расчётные подсказки остаются доступны.
- Общие Markdown-утилиты не менялись: бот использует legacy Markdown.
  Графики остаются SVG-документами, без новой зависимости для PNG.

Отправка реальных сообщений Telegram и обращения к настоящей нейросети
не входят в автоматические тесты.

Последняя проверка: Python 3.13.18, pytest 9.1.1 — 162 теста прошли.
Ruff 0.16.10: проверка кода и форматирования прошла; git diff --check — без ошибок.
